# 句段范本检索复核

`cases.json`：四节各10个构造的代表性写作需求。包含内容/功能交叉、跨节借句及无匹配负例，不称为40项作者已验收的真实请求。

查询同时使用 `query/function/need`；仅传宽泛 function 会丢失本轮细动作区分。首轮7个误导场景的修复由 `_shared/indexing/tests/test_query_feedback.py` 回归：I05/T01/T02/T06/T09/R06 首条定位正确动作，T07 明确返回缺口；条件适配、原文/模板差异继续单列。

合并后另复核 R10：需要保留混合发现的收尾使用源卡定义 `results.mixed_closure`，不能由一致强支持的收束句顶替。检索编号、UID、候选角色和版本绑定到同一次使用；开发期复核不写真实使用台账。

`run_benchmark.py --out <路径>`：保存查询、top-3、上下文、耗时及全量卡片内原句定位检查。结构和返回率不表示适配率。

`review-decisions.json`：实施者按原句、模板、动作和适用条件作出的开发期判断；不是独立盲评，作者接受未测。改动检索或语料后，应重新逐题审查判断与候选位置，不自动沿用旧结论。

当前复核绑定所选 UID、请求及检索/语料依赖指纹。`build_review_report.py` 在这些绑定不一致时拒绝导出，避免新排序沿用旧位置。首轮误导标记以 `first_misleading_before_repair` 保留，本轮判断另记；原文与模板不在这里重复存储。

`build_review_report.py --benchmark <结果JSON> --out-dir <输出目录>`：将已复核的选择绑定到该次候选UID、依赖哈希与源卡，导出可审查表和模板。若检索/语料变动，先更新复核再导出；不能仅运行导出工具就声称重新完成内容审查。

真实反馈使用 `_shared/indexing/log_exemplar.py`；这里的基准与试验使用隔离 `--home`，不写作者真实使用台账。下一轮可加入作者提供的真实句段，并另报作者采用与接受结果。

2026-10-01 细功能定义首批：依据上述开发期复核的误匹配及用户提出的动作区分，在四节现有卡片元数据中补充定义。权威位置由 `retrieve.py --list-functions` 的 `source` 字段给出；维护协议见 `../../_shared/exemplar-retrieval.md`。首批不是穷尽分类，也不把开发期复核称为真实作者使用反馈。让步后维持预测方向的完整模板已有，当前源块的文章摘录只含承认，完整原文范本仍待补。后续扩展先补已有源卡，再重建目录；此目录不维护第二套功能或范文正文。

第二步分层检索的回归见 `_shared/indexing/tests/test_layered_retrieval.py`：核验功能优先于主题、条件优先于主题、明确冲突排除、缺失事实保持未知、连续动作的顺序及同篇原文依据，并检查补充候选关联同一次检索。风险承认→设计移交的定义与条件写入现有 DiD/Heckman/IV 源卡；档案顺序有冲突时不能作为主候选。40个旧场景继续保留为兼容性回归，不把这些构造检查计作真实作者接受或独立复核效果。

来源排序变化复核补充：R09 的实际间接效应报告与 legacy Kenny 条件计数分开，现代需求不由来源更完整的 legacy 声明替代；legacy 的原文与验证状态保留。T03 的配对事件概率形式显式要求配对单元、配对自变量与事件概率结果，未确认时显示待核对，明确不符时排除。
