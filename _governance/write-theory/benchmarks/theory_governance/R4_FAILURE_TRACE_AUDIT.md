# R4 failed-task retrieval and transformation audit (2026-08-07)

## Evidence boundary

The original governed generator was asked, immediately after R4, to report only
commands and assets retained in its context.  The three query results were then
reproduced against the current catalog.  The benchmark did not persist an
immutable command trace, so the command history below is a corroborated

## RQ01: disclosure specificity × breach verifiability

Actual route:

- architecture: `theory:architecture:E`
- query: `bilateral sign-flipping boundary high low condition`
- rendered: `theory:pattern:bilateral_moderation_derivation`
- evidence state: `EMERGING`
- source: `subprotocols/hypothesis_derivation_patterns.md`

The query correctly ranked the bilateral asset first, and the generator rendered
its metadata-anchored fragment.  It transferred the high/low symmetric move,
created distinct corroboration and unverifiable-precision mechanisms, omitted an
unconditional main effect, and did not copy the source domain.

The loss (38 versus 40) was therefore not a retrieval-coverage failure.  It was
a transformation-precision failure.  The final argument graph placed the
boundary condition after the credibility inference rather than before the two
branches, weakening the causal ordering.  The legacy output also stated the
low-state warrant more sharply: uncheckable precision constrains alternative
interpretations and is therefore attributed to narrative control.

Classification: **correct asset; slightly weaker domain transformation**.

## RQ03: allegation → investigation → reform process

Actual route:

- architecture: `theory:architecture:D`
- query: `three-stage process transition actor condition observable failed branch`
- leading candidates: `three_element_citation_mechanism_anchor`,
  `multi_actor_interview_grounding_dual_path`, and generic argument assets
- rendered reference: none, because no candidate matched the transition need
- direct source: `variants/D_process_theory.md` plus generation contract

The generator correctly declined to force an irrelevant exemplar and built the
three stages from the structural D contract.  It supplied actors, thresholds,
markers, failed branches, and propositions.  However, the first transition used
independent counsel and a preservation order as its marker; those are already
acts of the investigation stage rather than a clean output of triage.  This
blurred `current state → transition marker → next state`.  Proposition grain also
varied across stages.

The current corpus has no metadata-addressable D reference for a complete
actor–condition–marker–failed-branch sequence.  The D variant is a useful
architecture, but catalog search cannot retrieve a precise process operator.

Classification: **reference-coverage gap plus stage-boundary transformation
error**.

## RQ04: alliance-repair feedback branching

Actual route:

- architecture: `theory:architecture:D`
- query: `feedback recipient reinforce redirect terminate open process`
- leading candidates: `no_global_closure`,
  `anchor_mechanism_warrant_prediction`, and
  `preemptive_competing_account_management`
- rendered reference: none, because the candidates were irrelevant
- direct source: `variants/D_process_theory.md` plus generation contract

The output identified a decision-capable recipient, three branches, observable
markers, and an open empirical agenda.  It lost narrowly (39 versus 40) because
it jumped from feedback sources to committee receipt.  The legacy output named
the missing transport mechanism: boundary spanners translate partner reactions,
missed milestones, and operating failures into comparable evidence for the
resource-allocating committee.

The current guard specifies a recipient and branch effect, but not the full
`source → carrier/channel → translation → recipient authority` chain.  Catalog
search also has no feedback-transmission reference to supply that move.

Classification: **reference-coverage gap and incomplete feedback-transport
operator**.

## System-level finding

The revised retrieval system worked as designed when a matching asset existed
(RQ01).  Both D failures exposed a genuine inventory hole rather than ranking or
rendering failure.  Adding more generic guard language or promoting benchmark
outputs as exemplars would be the wrong response.

The next repair, if authorized, should be narrow:

1. add an auditable retrieval manifest for evaluation runs (query, candidates,
   selected/rendered IDs, status, source file, fragment hash);
2. add structural D operators for clean stage boundaries and feedback transport,
   without treating them as paper-validated reference exemplars;
3. seek independent paper distills before creating or promoting D reference
   exemplars;
4. tighten E argument-graph ordering so the boundary condition precedes the
   condition-specific mechanism branches.
