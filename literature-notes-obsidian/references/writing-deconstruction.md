# Writing Deconstruction

Use this reference when the user wants to learn how a paper is written, not only what it says.

The goal is to turn a strong paper into a writing lesson that can improve three existing skills:

- `write-social-science-introduction`
- `write-theory-and-hypotheses`
- `write-methods-and-results`

Use `writer` mode in this skill as the lighter first pass. Use this file when the user wants a deeper transfer judgment about whether a paper's writing pattern should influence one of the three named skills.

## Principle

Separate two questions:

1. `What is the paper arguing?`
2. `How is the paper making that argument legible and persuasive on the page?`

Do not confuse analytical strength with writing strength. A paper may have strong identification but mediocre exposition, or elegant prose with weak logic.

## Layer 1: Introduction Deconstruction

Map the front end onto `write-social-science-introduction`.

Extract:

- hook type
- opening paraphrase or scene-setting move
- literature turn
- exact gap statement
- gap-value sentence
- paper move
- contribution focus
- roadmap or no-roadmap choice

Ask:

- Does the introduction behave like a relay: `title -> abstract -> introduction`?
- By the end of the first three paragraphs, can the reader see the conversation, blind spot, and paper move?
- Are there sentence patterns or paragraph transitions worth reusing?

Record transferable assets as rules, not admiration:

- bad: `This paragraph feels elegant.`
- good: `The gap paragraph uses current implication -> inadequacy -> why omission matters in four sentences.`

Treat `write-social-science-introduction` as conservative infrastructure. Do not update it lightly.

Use this decision rule before proposing any change to that skill:

1. `typical`: the exemplar represents a recognizable introduction type rather than one paper's personal style
2. `missing`: the current skill lacks guidance for that type
3. `stable`: the observed pattern is structural enough to teach, not merely stylish
4. `approved`: the user agrees that this is a worthy pattern to absorb

If any of the four fail, keep the lesson in the literature note and do not patch the skill.

## Layer 2: Theory and Hypotheses Deconstruction

Map the middle front end onto `write-theory-and-hypotheses`.

Extract:

- how constructs are introduced and bounded
- how the paper distinguishes neighboring constructs
- how the mechanism chain is staged
- how citations support rather than replace explanation
- how hypotheses are bridged from prose
- whether direction and operational coding stay aligned

Ask:

- Where does the paper do real explanatory work?
- Does the theory paragraph move from claim -> support -> analysis -> hypothesis bridge?
- Does the section avoid citation dumping?

Record transferable assets as rules or micro-patterns:

- `Introduce the construct with scope and nearest-neighbor differentiation before using it in the mechanism.`
- `End the paragraph on the implication that makes the hypothesis feel earned.`

## Layer 3: Methods and Results Deconstruction

Map the empirical middle onto `write-methods-and-results`.

Extract:

- sample funnel logic
- measure exposition order
- model or estimator explanation
- hypothesis-test reporting rhythm
- interaction exposition pattern
- robustness vs post hoc separation
- claim-evidence alignment

Ask:

- Does the methods section explain why the design is credible, not only what was done?
- Does the results section avoid table-reading?
- How does the prose translate coefficients or model outputs into bounded substantive meaning?

Record transferable assets as stable empirical-writing patterns:

- `Restate the hypothesis in compact form, point to the model, report the result, then interpret boundedly.`
- `Separate threat -> additional test -> implication in robustness paragraphs.`

## Promotion Rule For Updating The Named Skills

Only promote a pattern into one of the three named skills when all four conditions hold:

1. `excellent`: the pattern clearly improves clarity or persuasion
2. `repeatable`: it is not dependent on one paper's idiosyncratic topic
3. `compatible`: it fits the target skill's existing philosophy
4. `compressible`: it can be stated as a short rule, checklist item, or micro-example

If a pattern fails any of the four, keep it inside the literature note only.

For `write-social-science-introduction`, add an extra gate:

5. `introduction-type gate`: the source paragraph must exemplify a distinctive introduction type that the skill does not already cover.

This means:

- Do not change the skill because an introduction is simply strong.
- Do change the skill only when the introduction teaches a new, reusable type or routing pattern that is currently absent.

## Promotion Output Format

When a pattern seems promotable, capture it inside the note using this mini-template:

```markdown
## Writing Transfer Candidate
- Target skill:
- Source passage:
- Why it works:
- Generalized rule:
- Where it should live in the target skill:
- Confidence: high / medium / low
```

## What To Avoid

- Do not promote purely stylistic flourish with no reusable logic.
- Do not patch a target skill with topic-specific content unless the skill is topic-specific.
- Do not let one famous paper override the target skill's broader structure.
- Do not mistake sentence beauty for argument architecture.
- Do not revise `write-social-science-introduction` because of a single attractive opening unless it clearly reveals a missing introduction archetype.
