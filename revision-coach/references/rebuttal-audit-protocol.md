# Rebuttal Audit 协议(模式 B:回复体检,只审不写)

本文件支撑 revision-coach 模式 B。改编自 ARS `rebuttal-audit` 模式,去掉流水线专有的 Schema / verified-status 机制,保留 advisory 体检内核。

## 适用与路由
- **输入门**:必须**同时**提供 (a) 审稿意见 / 决定信,与 (b) 已写好的回复/反驳草稿。缺任一就别进本模式:
  - 只有 (a)、没有 (b) → 走模式 A(revision-coach 生成骨架)。
  - 两样都有 → 走本模式 B。
  - 不清就问,不要猜。

## 它产出什么(advisory 报告)

1. **逐条覆盖表**——把回复草稿与每条审稿意见对齐,逐条标:
   - `addressed`(已正面回应且有证据)
   - `partially`(回应了但不到位/证据不全)
   - `missing`(草稿里没回)
2. **缺口清单**——草稿没答上的关切,按优先级列出。
3. **风险标记**:
   - **语气过冲**(combative):直接否定、带情绪、读起来像辩论而非学术回应。
   - **无证据的断言**:声称"我们补了分析/表格"但没指向稿件具体位置,或位置不存在。
   - **误读审稿人论点**:回复答的不是审稿人真正问的(偏题、稻草人)。
   - **过度承诺**:承诺了稿件里没有、且短期做不出的东西。
4. **改进建议**(advisory)——针对每条 partial/missing/risk 给出怎么补,但**不替作者重写**。

## 报告模板

```markdown
## Rebuttal Audit Report(回复体检)

### 覆盖总览
- 审稿意见总数:[N] | 已答:[n] | 部分:[n] | 缺失:[n]
- 覆盖率:[n/N]

### 逐条覆盖
| concern_id | 审稿人 | 意见转述 | 状态 | 风险 | 说明 |
|---|---|---|---|---|---|
| R1-1 | R1 | … | addressed | — | 已指向 Table 3 |
| R1-2 | R1 | … | partially | 无证据 | 说法没指向具体页/表 |
| R2-3 | R2 | … | missing | — | 草稿未回应 |

### 缺口(按优先级)
1. [P1 缺口 + 为什么必须补]

### 风险标记
- **[R1-2] 无证据断言**:"补了稳健性检验"但未指 Table/Appendix → 建议指向具体位置,或标 PENDING 交 stata 执行。
- **[R2-1] 语气过冲**:回复开头"Reviewer 2 misunderstands…" → 建议改为"We appreciate the concern…; however, …"。
- **[R3-2] 误读论点**:审稿人问的是测量效度,回复答的是样本量 → 重新回应测量效度。
- **[对抗性异议] 缺降防御序列**:回复与审稿人存在根本性理论分歧(审稿人明确倾向竞争性解释)时,检查是否走了 Rogerian 四步(理解→承认成立条件→共同地基→共创方案,G&L 2017 Ch04;序列全文见 `write-theory/corpus/sentences/acknowledgment_response.md` §5)。直接反驳("We disagree because…")而无前两步,会把可争取的审稿人推向对立;同时警惕反向失格——ad hominem(攻击审稿人而非其论点)与 shifting the issue(转移话题)都是 rebuttal 场景的典型 fallacy。

### 改进建议(advisory,不代写)
- ……
```

## 铁律(integrity 边界)

- **只审不写**:本模式只对已有草稿出 advisory 报告,**绝不**生成新回复段落、**绝不**改写作者措辞。
- **不伪造已解决**:不得把 `missing`/`partially` 标成 `addressed`;不得输出"全部已回应""可投稿"之类的总体合格判定。它不是合格章,是体检单。
- **不替作者承诺**:体检只能指出"这里缺证据/这里误读了",要不要补、怎么补由作者决定。
- **实证类断言要核到物**:"补了分析"必须能在稿件里找到对应表/节;找不到就标 risk,不要替作者脑补它存在。

## 与模式 A、与其它 skill 的边界
- 本模式体检的是**回复信本身**(覆盖度、语气、证据);模式 A 是从零搭骨架。两者输入形态不同,不要混用。
- 它**不**核对"修改稿是否真的写进去了"——那需要把修改稿与回复信逐条比对,可由作者用 `paper-review` / `pollock-qc` 在修改稿上做,或人工核对。本模式聚焦回复信这一层。
