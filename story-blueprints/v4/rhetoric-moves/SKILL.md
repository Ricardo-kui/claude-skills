# 修辞动作润色器（自动匹配，无需点名动作）

把用户的草稿段升级为顶刊级表达。**用户只给草稿，动作由系统自动判断**——这是本技能与「用户报动作名」式调用的根本区别。

## 入口

用户说「润色这段」「改写这段」「升级一下表达」「太干了」「像 AI 写的」「怎么让它更有顶刊味」等，且给出草稿 → 进入本技能。若草稿来自 write-* 会话，同样适用（其锚点纪律与查重护栏共用本层）。

## 第一步：自动匹配动作（不读草稿不下笔）

1. 读 `_index.md` 动作分类表，浏览 6 个 move 文件的「动作定义」。
2. 按草稿的**修辞功能**打分匹配，不是按用户说的词：

| 草稿在做什么 | 匹配 move |
|---|---|
| intro 段：理论裁定前先用**两条对立文献预测**把问题立起来（一方面…另一方面…） | `bidirectional-staging` |
| theory 段：一个假设由**两条收敛因果链**推出（First… Second… 汇成一句假设） | `mechanism-two-chain` |
| theory 段：**N 个调节变量统摄于一个组织方案**下，读作一个论证而非三个附加 | `moderator-meta-framework` |
| results 段：**处理撤销/假处理/替代结局**，把结果推往相反方向或 null，作识别确证 | `counterfactual-reversal` |
| results 段：**补充分析织进正文叙事流**（前提探测/替代冲击/稳健性收束）而非压附录 | `additional-analysis-embedding` |
| results 段：结果**只在某条件下兑现**（高 W 反转、衰减 (a)(b)、双端兑现） | `conditional-payoff-closing` |

3. **匹配不到明确动作** → 只做微观打磨（衔接词/主被动/冗余压缩/句长），**不硬套 move**；并向用户说明「这段没有明显的修辞动作，只做了微观打磨」。

## 第二步：执行（严格走 `_polish-protocol.md`）

1. 读 `_polish-protocol.md`（整体 ∈[10%,40%]、单句单篇 ≤50%、引号豁免、跨源合成、流畅性门）。
2. 读对应 move 文件，按七段结构取料：**结构蓝图 → 信号词表 → 改写指引 → 只读参照（⚠️ 禁照抄，仅内化）→ 改写演示**。
3. 生成 2–3 个变体：保内容（领域术语/数字/因果主张/限定语）、升执行（逻辑序对齐蓝图、连接词/强调/缓和使用信号词、消冗余）。
4. 每个变体跑 `scripts/guard.py`，报告整体重合与单句单篇；不过护栏的变体重写或跨源合成。
5. 过流畅性门：主谓宾骨架可识别、单句 20–30 词（>40 拆句）、融合源 ≤3、搭配自然、保义保语气。

## 第三步：输出

- 变体 ×2–3，每个标注**实测整体重合 / 单句单篇**。
- 护栏报告 + 流畅性门结果。
- **指出草稿原来在尝试哪个动作**（教学性反馈：让用户逐渐认识动作，而不是要求提前背动作名）。

## 边界

- 只处理**单句/段落级**润色；整篇结构写作路由 write-*。
- 产出不携带只读参照长句；所有变体必须过护栏。
- 多段落、跨章节的润色建议分批处理，不把整个语料库倒给用户。
