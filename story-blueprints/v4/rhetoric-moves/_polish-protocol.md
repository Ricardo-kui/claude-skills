# 润色协议：用修辞动作语料升级你的语言表达（整体 ∈[10%,40%] 版）

**目标**：输入你自己的草稿句/段，输出 2–3 个**保留你的内容、升级修辞执行、整体重合度落在 [10%, 40%]** 的变体。首要标准是**通顺、符合学术表达习惯、句子不过长**；查重只是安全护栏。

**硬约束（用户裁决 2026-08-24，终版）**：不照抄任何一篇论文的句子。查重通过线 = **整体（与所有参照 4-gram 并集）重合度 ≤40%（硬拦截）**；另设**软目标 10%**——**低于 10%** 说明离范例修辞骨架较远（没借到该 move 的句式），提示回写更靠近骨架但**不拦截**；**高于 40%** 逼近查重风险（硬拦截）。另加**单句单篇 ≤50%**（硬拦截）与**引号豁免**：整句带引号直接引用一篇论文（强调用，学术惯例）整体剔除、不参与计算。**不是越低越好**——压到近 0% 会逼出堆同义词的硬凑句、牺牲可读性；适度吸收句式是正常的，逐篇照抄才危险。

**核心策略（用户提出）**：要压低重复度，**跨源合成**是正道——一句话综合多个顶刊范例的句式表达来拼装。每源只贡献一个句式片段（连接器/节奏/收束装置），整体占比自然落在区间内。

**危险点（用户预警）**：AI 强行拼接会让句子**不流畅、不自然**。因此本协议在查重护栏之外增设**流畅性门**——护栏管"像不像抄的"，流畅性门管"像不像人写的"。两道都过才输出。

## 工作流

```
用户草稿 → 1.识别动作 → 2.取蓝图+信号词(允许多源) → 3.保内容升执行 → 4.生成变体×3(含跨源合成)
         → 5.查重护栏(整体≤40%硬+<10%软提示+单句单篇≤50%+引号豁免) → 6.流畅性门(通顺/学术/句长) → 7.输出
```

### 1. 识别动作
读 `_index.md` 动作表，判断草稿在尝试哪个修辞动作（或由用户指定）。无法归类的草稿 → 不套动作，只做微观打磨（衔接词/主被动/冗余压缩）。

### 2. 取蓝图 + 信号词（**允许多源**）
读对应 move 文件的「结构蓝图」与「信号词表」。**若整体重合接近 40% 需要压低**：额外读 1–2 个其他 move 文件（或同一动作的其他论文范例）的信号词表，为跨源合成准备句式片段。**若整体重合接近 10% 需要抬高**（软目标）：回到该 move 的「只读参照」，确认骨架句（信号词链）是否被过度改写掉。**只读参照句用于内化机制，不搬进产出。**

### 3. 保内容，升执行
- **保留**：用户的领域术语、具体数字/发现、因果主张、限定语。绝不编造或替换用户的实质内容。
- **升级**：句子的逻辑排序对齐结构蓝图；连接词/强调/缓和使用信号词；消除冗余与僵尸名词化。

### 4. 生成变体 ×3（含跨源合成）

- **变体 A（单蓝图重排）**：按一个动作的蓝图重排逻辑序，换连接器。最稳，优先推荐。
- **变体 B（跨源合成）**：当整体重合接近 40% 需压低时；接近 10% 需抬高（软目标）时则回到单蓝图重排、保留骨架句。从 **2–3 个不同来源**各取一个句式片段，**结构级**拼接成一句：
  - 来源 1 供连接器/对比结构（如 "A first reading is that… Weighing against this…"）
  - 来源 2 供枚举/展开装置（如 "two distinct pathways… Externally… Internally…"）
  - 来源 3 供收束/裁定装置（如 "Which dominates depends on…"）
  - **内容词全部来自用户草稿**，句式片段只借"形状"不借"词语"。
- **变体 C（换主宾视角）**：主动↔被动、行动者↔机制主语、机制前置↔结果前置，保留用户结论。

### 5. 查重护栏（整体 ≤40% 硬拦截 + 软目标 10% + 单句单篇 ≤50% + 引号豁免，强制）

对每个变体，剥离引号段后计算与**所有参照来源**的整体重合度（候选非引文 4-gram ∩ 全部参照 4-gram 并集 的占比）；再逐句计算**单句单篇**（该句非引文 4-gram 与单篇参照的最大重合占比）。整体与单句单篇都过才判 PASS。

> **可执行脚本（P0 落地，2026-08-24；区间/豁免 2026-08-24 修正）**：算法已落地为 `scripts/guard.py`——CLI：`python guard.py "<候选>" --ref "<锚点A>" --ref "<锚点B>"`（或 `--candidate-file` / `--ref-file`），默认整体区间 [0.10, 0.40]、单句单篇 ≤0.50，退出码 0=PASS / 1=FAIL。判定逻辑：
> - **引号段（"…" / “…”）整体剔除**，不计入整体与单句单篇；
> - **整体重合 ≤0.40（硬拦截）**：>0.40 = 逼近查重，需跨源合成压低；**<0.10 = 软提示**（离骨架较远，回写保留骨架句，不判 FAIL）；
> - **单句单篇 ≤0.50**（建议）：防"稀释段落里某一句几乎整句照抄单篇"；
> - **下限豁免**：非引文散文 <15 tokens（典型=引号引文 + 简短出处）时只查上限与单句单篇；
> - **整段皆引文** → 自动豁免。
> write-\* skill 的锚点纪律会在生成后调用它做核验。

**判定**：
- **整体 ≤0.40 且各句单篇 ≤0.50** → 通过。到此为止，**不要再为降重复率继续换词**——把剩余精力花在通顺与句长上。
- **整体 <0.10** → **软提示，不拦截**（改写过度）。回该 move 的「只读参照」重建骨架句（信号词链），保留更多该 move 的信号句式——10% 是目标值不是闸门，通顺优先。
- **整体 >0.40** → 拦截。**优先改用跨源合成**（把该句的句式片段拆到多个来源，整体占比压到 ≤40%）；仍超则换句式骨架重写。
- **单句单篇 >0.50**（非引号直接引用时）→ 拦截。把该句与单篇参照重合的片段拆到别的句子（跨句分摊）或改写。
- 单句单篇是**独立于整体的第二道检查**：整体 ≤40% 时并集层必然 ≤40%（单源 ⊆ 并集），但"整段稀释、单句照抄"时整体会混过——所以按句单独卡 50%。整句带引号直接引用（强调用，学术惯例）豁免。

**护栏的边界**：整体 ≤40% 是查重红线、10% 是"借到骨架"的软目标——两者都是护栏**不是写作目标**。目标永远是通顺 + 学术表达习惯 + 句子适中。句子已通顺且整体落在区间内时，禁止为了更低的数字做无谓改写——那只会把句子改硬。

### 6. 流畅性门（通顺/学术/句长，强制）

跨源合成的最大风险是拼贴不自然。每个通过护栏的变体再过以下七查，**任一不过即作废该变体**：

1. **主句骨架可识别**：一句话必须能画出清晰的 主—谓—宾 主干；堆了 3+ 个并列从句且无明确协调词 = 拼贴。
2. **句子不过长**（用户裁决 2026-08-24）：单句以 20–30 词为常，超过 ~40 词必须拆句。宁可两句短句，不要一句长龙——句长是通顺的第一观感。
3. **融合源 ≤3**：一句话借用的句式来源超过 3 个 = 拼贴信号，拆成两句或砍掉最弱的片段。
4. **搭配自然**：每个 名-形 / 动-宾 组合须是英语惯用搭配；陌生搭配 >1 处 → 重写（如 "steeper growth bar" 可，"heightened visibility demands of the growth" 不可）。
5. **读诵测试**：默读一遍。有节奏、能一口气读完 = 通过；磕绊、无停顿逻辑 = 重写。
6. **保义保语气**：融合不得改变用户草稿的意思或语气（假设句不变成因果断言、限定语不丢）；改变即弃。
7. **humanizer 联动（可选）**：决赛句过 `humanizer` skill 的 AI 腔检查（僵尸名词化、过度形式化、句长失衡）。

### 7. 输出
给每个变体 + 护栏报告（每变体 max 单源重合分）+ 流畅性门结果（哪几查通过）。用户选一个，或要求再生成。

## 与现有资产的边界

- **Morley phrasebank（变化库）**：提供句子表面层改写变体，可充当跨源合成的"来源 3"（收束/措辞装置）；本协议在其上定"修辞动作意图层"。
- **humanizer（AI 味去除）**：既是减操作（去 AI 腔），也是流畅性门的第 6 查。顺序：先跨源合成升级，再 humanizer 验流畅。
- **write-\* corpus（功能模板）**：功能模板教论元结构，本层教句子执行。中文功能模板 + 本层信号词 = 完整执行路径。
- **多篇蒸馏联动**：跨源合成需要的"多来源句式片段"，来自不同论文的 distill 产物（blueprint 卡 + move 文件 + 各自只读参照）。蒸馏越多，可借的形状越多样，单源重合越容易压低——这是"综合多篇顶刊句式"能力的原料。

## 使用示例
见 2026-08-24 会话护栏演示：照抄整句 → 整体 1.00（拦截）；高仿单源 → >0.40（拦截）；近 0% 过度改写 → <0.10（软提示，回写骨架句，不拦截）；借骨架 + 换内容 → 整体 ∈[0.10,0.40]（通过）。落带内且句子通顺，即交付——不再追求更低。
