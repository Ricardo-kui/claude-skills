# Plot Emergence Check（情节浮现检查）

## 核心原则

> "Plot is emergent rather than formative... Plot emerges from the characters' interactions as you put them into situations and see what happens." — Pollock 2025, Ch02（引述 King 2000）

**关键区分**：
- **Plot 先于 Story（强加）**：先有假设，再扭曲构念定义以适应假设
- **Plot 浮现于 Story（自然）**：从构念定义出发，自然推导出假设

## 检测问题清单

对每个假设推导段落，问以下 5 个问题：

1. **"如果主角（protagonist）和配角（supporting）被放入这个情境，它们会自然地产生这种互动吗？"**
   - 如果答案模糊或需要"特殊条件"才能成立 → ⚠️ Plot 可能先于 Story

2. **"假设中的关系是否已经从构念定义中隐含？"**
   - 如果构念定义需要被修改才能支撑假设 → ⚠️ Plot 先于 Story
   - 如果构念定义自然蕴含假设中的关系 → ✅ Plot 浮现于 Story

3. **"如果换一个研究者，用同样的构念定义，会得出不同的假设吗？"**
   - 如果会 → 假设不是从构念中自然浮现的 → ⚠️ Plot 先于 Story
   - 如果不会 → 假设是构念逻辑的必然结果 → ✅ Plot 浮现于 Story

4. **"假设推导中是否有'为了得到这个结果，我们需要假设...'的句式？"**
   - 如果有 → ⚠️ Plot 先于 Story
   - 如果推导是"因为 X 的定义包含 A，而 A 导致 B，所以..." → ✅ Plot 浮现于 Story

5. **" reviewer 会说'这个假设看起来是强加的'吗？"**
   - 如果直觉上感到 forced → ⚠️ Plot 先于 Story
   - 如果感到自然、 inevitable → ✅ Plot 浮现于 Story

## 常见 "Plot 先于 Story" 模式

| 模式 | 表现 | 检测信号 | 修复 |
|------|------|---------|------|
| **构念扭曲** | 为了支撑假设，修改构念的定义或 scope | 构念定义在假设推导段落与 T1 定义不一致 | 回到 T1，统一构念定义，重新推导 |
| **机制拼凑** | 从多个不相关的理论中拼凑机制 | why chain 中每一步来自不同理论，无内在联系 | 选择一个核心理论，确保机制链条内在一致 |
| **假设倒推** | 先确定想要的假设方向，再构造理论 | 理论推导中有"为了解释 X 对 Y 的正向影响"等目的论表述 | 从构念出发，让假设自然浮现，不预设方向 |
| **配角抢戏** | 配角（moderator/mediator）的引入感觉突兀 | 配角在假设推导前缺乏充分的定义和铺垫 | 提前定义配角，说明它与主角的自然联系 |
| **情境强加** | 实证情境被选择来"验证"假设，而非"检验"理论 | "我们选择 X 行业因为数据支持我们的假设" | 选择情境应基于理论适用性，而非数据便利性 |

## 范文：Mishina et al. (2010) 的 Plot Emergence

**主角**：Performance relative to aspirations/expectations
**配角**：Firm prominence
**情境**：High-performing firms engaging in illegal actions

**Plot 浮现过程**：
1. 构念定义：Performance relative to aspirations = 实际绩效 - 内部/外部期望
2. 自然蕴含：高绩效 → 高期望 → 维持压力 → 违法动机（loss aversion / house money / hubris）
3. 配角引入：Prominence = 企业受关注程度（自然与压力相关）
4. 自然互动：高 prominence 的企业感受到的维持压力更"acute"
5. 假设浮现：Prominence 调节 performance→illegality 的关系

**为什么是 Plot 浮现于 Story？**
- 如果不引入 prominence，故事仍然完整（H1-H2 已 tying 了主 knot）
- Prominence 的引入不是"为了得到调节效应"，而是"高绩效企业的压力自然与其受关注程度相关"
- 在早期版本中，他们考虑过 reputation 作为配角，但最终选择 prominence，因为 prominence "cohered" with the story

## 修复动作

### 如果检测到 "Plot 先于 Story"

1. **回到构念定义**：
   - 检查 T1 的构念定义是否被假设推导段落修改
   - 如果被修改 → 统一定义，以 T1 为准

2. **重新从构念出发推导**：
   - 列出构念的所有自然属性
   - 问："这些属性在目标情境中会自然产生什么互动？"
   - 不要让"想要的假设"引导推导

3. **检查理论一致性**：
   - why chain 的每一步是否来自同一理论框架？
   - 如果不是 → 选择一个核心理论，或明确说明理论整合的逻辑

4. **让配角自然出场**：
   - 配角不应是为了"增加复杂度"而引入
   - 配角应与主角有自然的理论联系
   - 如果配角感觉突兀 → 删除或替换

## 与 "Extraneous Storyline" 的区别

| | Plot 先于 Story | Extraneous Storyline |
|---|----------------|---------------------|
| **问题** | 假设推导不自然，构念被扭曲 | 段落与 central knot 无关 |
| **位置** | 假设推导段落 | 任何段落 |
| **修复** | 回到构念定义，重新推导 | 删除或降级 |
| **检测** | 5 个问题清单 | "去掉后 knot 是否仍完整？" |
